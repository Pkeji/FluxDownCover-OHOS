# FluxDown 0.4.7 反编译报告与鸿蒙移植差距分析

生成时间：2026-09-05
对象 APK：`FluxDown-0.4.7-android-universal.apk`（109 MB）
鸿蒙工程：`FluxDownCoverOHOS`（包名 `com.example.myapplication`）

---

## 一、结论摘要

1. **APK 的业务代码无法反编译为可读源码**：该应用为 Flutter + Rust 混合架构，Dart 业务代码以 AOT 快照形式编译进 `libapp.so`，Rust 引擎编译进 `libhub.so`（已 strip 符号表）。二者均为机器码，不存在等价的源码还原手段。
2. **但已找到更有价值的替代品**：FluxDown 是开源项目，官方仓库含 **完整 Dart + Rust 源码**，已克隆至 `/Users/Zhuanz/fluxdown-src`。源码与本次 APK 基本同代（仓库 i18n 1722 条 vs APK 1685 条）。
3. **完整移植是十万行量级的工程**，无法一次性完成，必须分阶段；且其中账号/云同步/支付/插件市场依赖服务端与原生动态库生态，在鸿蒙上不可直接移植。

## 二、反编译结果

### 2.1 技术栈判定

| 证据 | 判定 |
|------|------|
| `lib/arm64-v8a/libflutter.so`（11.7 MB）、`assets/flutter_assets/` | Flutter 应用 |
| `lib/arm64-v8a/libapp.so`（6.4 MB） | Dart AOT 快照（业务代码），非 Java |
| `lib/arm64-v8a/libhub.so`（17.5 MB）+ `package:rinf` | **Rust 核心引擎**（Rinf = Dart/Rust FFI 框架） |
| Dart 快照中的版本号 `3.3.3` | Dart SDK 3.3.3 |
| `libsuper_native_extensions.so`、`libirondash_engine_context_native.so` | 剪贴板/拖拽原生扩展 |
| Flutter 插件（快照中 `package:` 引用） | `rinf`、`slang`（i18n）、`shadcn_ui`、`boxy`、`flutter_animate`、`flutter_local_notifications`、`url_launcher`、`path_provider`、`file_selector`、`shared_preferences`、`super_native_extensions` |

### 2.2 各层反编译可行性

| 产物 | 工具 | 结果 |
|------|------|------|
| `classes.dex` + `classes2.dex`（876 个类） | jadx | ✅ 成功，但**仅为 Flutter 框架与插件桥接代码**（`io.flutter.*`、`androidx.*`、`com.dexterous.*`、`dev.irondash.*`、desugar 的 `j$.time`），**无任何 FluxDown 业务代码** |
| `libapp.so`（Dart AOT） | — | ❌ AOT 快照，无字节码/元数据可供反编译为 Dart 源码；仅能提取字符串表（31866 条） |
| `libhub.so`（Rust） | `nm -D` | ❌ 已 stripped，仅剩 268 个动态链接符号；panic 字符串只暴露第三方依赖源码路径（hyper、socks、zstd、openssl），无 `hub` 自身模块路径 |

## 五、差距分析与可行性分级

### A 级 — 可完整移植（纯本地功能，建议优先）

| 功能模块 | 现状 | 需补 |
|----------|------|------|
| **BT 引擎** | 有基础下载（磁力/种子/分片/PeerWire） | DHT 完整实现、UPnP 端口映射、做种策略（分享率/时间/不活跃/最大活动数）、Tracker 列表与订阅更新、上传限速、续种、重新检查 |
| **队列系统** | 仅并发数/优先级/自动开始 | 每日定时启停（含补触发）、队列级限速、队列级 UA、队列级线程数、任务拖拽排序 |
| **分类管理** | 仅有 `category` 字段 | 自定义分类（名称+扩展名规则+独立保存目录+优先级排序） |
| **任务详情** | 基础信息 | 分段/连接信息、速度曲线、BT 面板（peers/trackers/分享率）、做种控制 |
| **任务操作** | 暂停/恢复/删除 | 重命名、移动到目录、重新检查（recheck）、失效任务清理、批量删除（保留/删除文件二选一） |
| **筛选与搜索** | 无 | 状态筛选、分类筛选、关键词搜索 |
| **HLS/DASH** | 有下载 | 清晰度/轨道选择 |
| **设置体系** | 主题、配色、分段、限速、剪贴板、镜像 | 语言、显示密度、代理（真正接入请求）、通知开关、下载完成后动作 |
| **系统分享** | 有 `sendData` 入口 | 完善冷/热启动、多文件、文本解析 |

### B 级 — 部分可移植（工作量大或需替代方案）

| 模块 | 说明 |
|------|------|
| 网盘/直链解析插件 | 原为 Rust 插件 + 远端脚本；鸿蒙可考虑内置 JS 引擎执行解析脚本，或仅移植若干常见站点的解析规则 |
| CDN 加速 | 依赖服务端节点，本地仅能保留接口与开关 |
| Webhook / 本地管理 API | 可本地实现事件回调与 HTTP API，但无云端中转 |

### C 级 — 不可移植（依赖服务端或原生生态）

| 模块 | 原因 |
|------|------|
| 账号系统（邮箱验证码/密码登录、Origin ID、设备信任、套餐购买、邀请码返利） | 依赖官方 FluxCloud 服务端（`/api/v1`、`/auth/refresh`） |
| 云配置同步、多设备协同与推送下载 | 同上 |
| 插件市场（Rust 动态库插件安装/卸载/权限/熔断） | 依赖远端市场与动态库加载机制，鸿蒙不支持 |
| 桌面特性（托盘、窗口置顶、开机启动、文件关联） | 鸿蒙移动端无对应能力 |
